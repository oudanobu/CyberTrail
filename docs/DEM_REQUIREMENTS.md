# CyberTrail DEM 数字高程模型用户指南 & 格式要求说明

本篇文档面向 **户外运动爱好者（登山、徒步、越野、探险）** 以及 **GIS（地理信息系统）专业用户**，详细介绍如何在 CyberTrail 移动端正确配置与导入离线数字高程模型（DEM）数据，以实现绝对离线的海拔、坡度及坡向实时分析。

---

## 1. 核心架构背景
**CyberTrail 不内置、不提供、不捆绑任何商业或免费的 DEM 高程数据。**  
为了保护用户隐私并实现 100% 离线自主性，所有的 DEM 数据完全由用户自行下载、裁剪并导入设备。

在最新版的 CyberTrail DEM 引擎中，采样逻辑已经全面重构：
- **元数据动态读取**：系统将自动读取 GeoTIFF 元数据标签中的物理坐标参考与像元比例，拒绝使用硬编码的采样步长。
- **分辨率自适应**：自动计算 DEM 在当前纬度下的真实投影距离（Meters），无论是超高精度的 `1m LiDAR` 还是广域 `90m SRTM`，系统均能精准感知，零配置兼容。
- **像素级精准采样**：坡度（Slope）与坡向（Aspect）的差分计算，严格基于相邻像元的高程差与物理像元尺寸（$dx, dy$），彻底避免了由于固定小步长引起的“同像元重复采样”导致的阶梯状伪影。

---

## 2. 格式与元数据要求

### 2.1 支持的文件格式
系统采用底层二进制流直接解析标准栅格，因此对文件格式有严格的筛选：

*   **✅ 完美支持**：
    *   **GeoTIFF 格式**（扩展名为 `.tif` 或 `.tiff`）
    *   **单波段高程栅格**（Single-band elevation raster，其中波段存储的每个像素值代表真实的物理海拔，单位为**米/Meters**）
*   **❌ 绝对不支持**（导入后将无法加载或报错）：
    *   **通用图像格式**：`.png`、`.jpg`、`.jpeg` 等。
    *   **渲染图/效果图**：山体阴影图（Hillshade）、坡度图、坡向图、普通手机地图截图。
    *   **彩色地形渲染图**：看起来有高低起伏色彩，但实际丢失了真实高程数值的普通 RGB 栅格图。

### 2.2 必须包含的地理元数据
一个合法的 GeoTIFF 必须在文件头部携带完整的地理定位标签（GeoKeys）。若使用 GIS 工具（如 QGIS、ArcGIS 或 gdalwarp）导出时，**请务必保留以下元数据**：

1.  **CRS（坐标参考系统）**：定义文件所处的地理或投影坐标系。
2.  **GeoTransform / TiePoint（仿射变换与地理控制点）**：关联图像像素坐标 `(Col, Row)` 与地理坐标 `(Lon, Lat)` 的换算矩阵。
3.  **PixelScale（像元比例/分辨率）**：定义单个像素代表的实际地理跨度。

> ⚠️ **重要提示**：如果 GeoTIFF 缺少上述元数据（沦为普通的无地理参考 TIF 影像），CyberTrail 引擎将**无法定位当前 GPS 位置对应的像元**，从而导致海拔、坡度、坡向显示均为 `N/A`。

## 3. 推荐坐标系（CRS）

*   **推荐坐标系：`EPSG:4326 (WGS 84)`**
*   **坐标表示形式**：经纬度坐标（例如：`Lat: 40.123665`, `Lon: 124.389216`）

**原因**：  
CyberTrail 当前以 WGS84 原始经纬度作为系统内标准坐标。若导入的 GeoTIFF 为 EPSG:4326，解析速度最快，计算开销最小，能够显著延长移动设备在户外高频采样时的续航时间。
*注：系统在读取时会自动检测并进行坐标适配，但推荐优先使用地理坐标系 WGS 84。*

## 5. 分辨率兼容性
CyberTrail **不依赖任何硬编码的 DEM 分辨率**。  
我们底层的 GeoTiffReader 会动态解析图像宽高以及像元尺寸：
- 如果您导入的是 `12.5米 (如 ALOS 修正版)` 或是 `10米/5米` 高精度切片，系统会自动识别并将采样步长对齐为 $dx = 12.5\text{m}$ / $5\text{m}$。
- 如果是 `90米 (SRTM3)` 粗略数据，系统亦会宽容适配。
- **完全即插即用**，用户无需在 App 内手动修改任何分辨率设置。

## 6. DEM 文件放置规范与路径

### 6.1 物理路径
请将您下载或裁剪好的 `.tif`/`.tiff` 文件，存放到 Android 设备内部存储的指定目录下：
`/storage/emulated/0/CyberTrail/dem/`

*提示：如果文件夹不存在，请手动创建，或在 App 首次启动授予存储权限后由系统自动生成。*

### 6.2 多文件共存与智能检索
- **支持多文件共存**：您可以同时在 `dem/` 文件夹下放置 `dandong_dem.tif`、`beijing_dem.tif`、`hokkaido_dem.tif` 等。
- **智能重叠检索**：当您处于某一 GPS 位置时，CyberTrail 的 `DEMLoader` 检索器会**自动扫描并匹配**物理范围能够覆盖您当前坐标的那个文件。
- **零手动切换**：跨省、跨国运动时，系统会在后台实现无缝过渡，不需要人工进入设置页面频繁切换当前文件。

### 6.3 最佳裁剪建议
请**避免**直接把“全国 DEM”或“全球 DEM”等数个 GB 的超大完整文件塞入手机。  
*   **推荐做法**：使用 QGIS 或在线裁剪工具，仅将您本月或本季度计划活动的城市/山脉（例如：东经 123°~126°，北纬 39°~42° 的丹东及周边区域）裁剪成独立的小 `.tif` 文件。
*   **收益**：
    1.  文件体积可缩小至数十兆（MB），下载和拷贝极快；
    2.  大幅节省手机运行内存（RAM），防止后台被系统强制杀掉进程；
    3.  极大提高地图初始化和首次定位高程的载入速度。

## 7. 常见问题 FAQ

### Q1：为什么我的高程显示为“DEM 未加载”或“N/A”？
*   **排查步骤**：
    1.  **文件路径错误**：确认文件是否存放在 `/storage/emulated/0/CyberTrail/dem/` 目录下，文件后缀是否为小写 `.tif` 或 `.tiff`。
    2.  **GPS 未定位**：系统必须获得当前 GPS 位置才能在 DEM 中检索对应像元。请确保手机 GPS 已经成功定位。
    3.  **坐标越界**：您当前的 GPS 位置不在您导入的任何一个 DEM 文件的边界范围（Bounding Box）内。
    4.  **权限缺失**：进入手机系统设置，检查是否已授予 CyberTrail “所有文件访问权限” 或 “读取外部存储” 的权限。

### Q2：高程显示正常，但为什么坡度和坡向显示为 “N/A” 或 “0°” 保持不动？
*   **排查步骤**：
    1.  **数据精度过低或步长重合**（已通过算法重构解决）：早期版本的计算公式会由于采样步长小于像元尺寸导致采样点落入同一像素，从而出现局部坡度全部为 0 的情况。最新版本已实现自适应像元级采样，若仍出现，请检查您的 `.tif` 文件在当前坐标处是否全为异常平整的死值或空值（NoData）。
    2.  **地势极其平坦**：当坡度低于极小阈值时，坡向将解算为 `无坡向 (null)`，这是正常的地理学物理现象。

### Q3：为什么导入后高程数值严重失真？（例如丹东平地显示高程几千米，或者变成负数）
*   **排查步骤**：
    1.  **单位不匹配**：您的 DEM 并非以米（Meters）为单位，或者属于未投影的 raw 灰度图。
    2.  **坐标投影混淆**：您的 GeoTIFF 采用了非标准的局部局域投影（如特定的 Gauss-Kruger 3度带），而没有提供正确的仿射转换参数，导致系统换算像素坐标时发生严重偏移，读取到了几百公里外的其它像元高程。
    3.  **推荐重新转换**：使用 QGIS 的 `重投影 (Warp/Reproject)` 功能，将目标文件强制投影为 `EPSG:4326` 后再导出。

### Q4：如何检查我的 GeoTIFF 是否包含合法的地理参考信息？
*   **方法一（电脑端，推荐）**：  
    安装 GIS 命令行工具 `GDAL`，在终端运行：
    ```bash
    gdalinfo your_dem_file.tif
    ```
    检查输出中是否包含：
    *   `Coordinate System is:` (应该显示 WGS 84 或其它已知 CRS)
    *   `Origin = (...)`
    *   `Pixel Size = (...)`
*   **方法二（QGIS）**：  
    将 `.tif` 直接拖入 QGIS 软件中，双击图层查看“属性 (Properties) -> 信息 (Information)”，检查其 Coordinate Reference System 是否显示为有效的坐标系，且 Extents 范围是否与您预期的经纬度数值一致。
